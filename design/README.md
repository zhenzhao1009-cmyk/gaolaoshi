# Bloom · 指尖花开：交互体验方案

参赛定位：创意赛道 → 数字媒体设计 → 交互设计。
作品名称：《Bloom·指尖花开——基于视觉手势识别的花卉交互体验设计》。

## 设计主张
以手为笔，让花绽放。把花朵的开放过程变为可亲手掌控的时间，让观众通过捏合、数指、展掌与挥手建立动作和视觉变化的联系。
第一版定位为面向电脑浏览器的花卉互动体验。竖屏模式用于展示和录屏；手机浏览器的真实摄像头表现仍需实机验证。

## 完整界面
- 上部约 56%：花朵画布。顶部品牌与五种花导航；左下花名、拉丁学名、短句与开度；底部操作提示与可见控制。
- 下部约 44%：摄像头与反馈。未开启时提供“开启摄像头”和“先看演示”；右侧显示左右花状态、手势规则、手动开度、设备选择和减少动效。
- 操作指引：独立对话框，按“举手入镜 → 让花开放 → 展掌与换花”讲解。
- 窄屏：自然纵向排布，允许滚动；竖屏录制模式保留主要控制，紧凑展示。

## 输入与反馈
| 输入 | 反馈 |
| --- | --- |
| 全花种：拇指与食指捏合 | 连续控制开度，其他三指收起 |
| 全花种：伸出 0–5 指 | 花朵按六个阶段平滑开放；两指时由捏合距离连续微调 |
| 展开手掌 | 盛放，倾斜手掌调整角度；达到阈值时飘瓣 |
| 水平挥手 | 右挥下一朵、左挥上一朵，抑制回程误切 |
| 双手 | 初次按画面左右绑定，随后结合位置预测与模型左右手标签追踪；双花仅在两只手同时可见时进入，任一手离开自动回到单花（手动开启除外） |
| 手暂时离开 | 保持开度，停止飘瓣和手掌旋转；超时释放追踪 |
| 手动滑杆或按键 | 更新真实开度，并短暂优先于实时手势 |
| 自动演示 | 自动开合，每 10 秒换花，支持随时停止 |
| 纯净画面 | 隐藏导航与反馈面板，保留退出入口，便于录屏 |

追踪在完全遮挡、重新入镜和模型左右手分类错误时仍可能重新分配，需实机评估。当前不宣称支持稳定的多人身份识别。

## 状态与恢复
摄像头：未开启 → 准备中 → 运行中；任何启动失败都保留重试按钮。模型初始化先尝试 GPU，失败再尝试 CPU。连续识别异常会释放摄像头并提示重试，花卉预览和动画循环继续可用。
素材：待加载 → 加载中 → 可用；颜色图与遮罩必须配对成功才切换到素材绘制。缺失、损坏或不可用时回退到立体花。

## 实现与验证
- 修正归一化坐标的画面宽高比，避免同一手势旋转后开度大幅变化。
- 键盘、滑杆共享状态更新逻辑，闭合时同步清除飘瓣状态。
- 仅加载当前可见花种；单花最多保留 48 张缩小后的帧，最长边 640 像素；双花共享 96 MiB 的解码像素预算，切换后释放非可见缓存。此预算不等于浏览器总内存。
- 保持模型、识别库和界面字体离线可用。
- 回归检查：在项目目录执行 node tools/test_interactions.cjs。当前 25 项模拟逻辑检查通过。
- 本机浏览器进程启动受权限限制；实际摄像头成功率、实际帧率、布局和触屏操作需要补充实机验证。
